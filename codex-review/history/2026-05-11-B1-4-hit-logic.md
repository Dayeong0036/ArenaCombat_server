## Key Design Decisions Recorded

1. **Parry semantics**: any-parrier-blocks-all (mirror legacy 2D). Boss wide-attack balance question deferred to B3.
2. **maxHitTargets cap**: applies to RPC payload only, NOT damage. Damage applies to all eligible.
3. **Reject feedback contract**: gameplay reject (cooldown, missing data) = owner-only via ExecuteQueuedAttackAction. Resolved combat events (hit/miss/parry) = broadcast.
4. **parryStunTimer**: second one-off timer pattern (after invulnerabilityTimer). Acceptable mirror; future Phase B+ may consolidate into source-tagged status duration model.
5. **Registry validation**: hit filter requires target's PNC3D to match `players3D[clientId]` exactly. Defends against stale/unregistered objects on the layer.
6. **playerLayer empty warning**: surfaces scene setup mistakes immediately at OnNetworkSpawn.
7. **hitTargets semantics**: B1-4 ships "hitbox-eligible" (includes invulnerable targets that TakeDamage silently rejects). B1-5 must refine to "actually damaged" for K/D/A and kill feed accuracy.

## Lessons

- **Three rounds for substantial new logic**: each round caught a different class of issue (R1 design questions, R2 security/correctness, R3 lifecycle). Worthwhile slow process for accuracy/stability priority.
- **CI-B1-4-R1-1 (ApplyParryStun=0 permanent stun)**: subtle bug because `[Min(0f)]` is permissive — "min 0" doesn't mean "should be > 0". Defensive: add explicit early return when feature is disabled-by-zero.
- **CI-B1-4-R1-2 (registry validation)**: Physics.OverlapBox returns ALL colliders on the layer, including objects that aren't in your gameplay registry. Always validate against your authoritative tracking dict. Pure GetComponent isn't enough.
- **S-B1-4-R1-2 (cap order)**: cap-during-loop loses ordering invariants. Build complete intermediate state, apply cap only at the wire boundary.
- **S-B1-4-R1-5 (reject duplication)**: when both server gate (CombatManager3D early reject) and client gate (ExecuteQueuedAttackAction reject) exist, decide ONE direction for each rejection class. Owner-only for gameplay-rule rejects, broadcast for resolved combat events. Don't double-fire.
- **S-B1-4-R2-2 (hitTargets semantics)**: vague semantics in shipped contracts (here: "what does hitTargets mean — eligible? damaged?") become entrenched fast. Document explicitly even if not refined in current cycle.
